# 演示指南

> 如何在面试中有效使用这个个人网站展示技术能力

## 🎯 演示准备

### 页面结构
```
首页 (Home)
├── Hero Section - 个人简介
├── 技能展示 - 技术栈可视化
├── 项目展示 - 3 个核心项目
└── 联系方式 - 快速联系

关于页 (About)
├── 个人简介
├── 工作经历
├── 教育背景
└── 技术认证
```

### 设备准备
- 笔记本电脑（备用投影仪）
- 移动设备（应对不同场景）
- 预先安装的浏览器（Chrome/Edge）

## 📋 演示步骤

### 1. 网站访问（30 秒）

```bash
# 在面试现场
打开浏览器 → 输入你的个人网站 URL

# 如果网站未部署，使用演示模式
npm run dev -- --host  # 让面试者查看你的屏幕
```

**面试话术**:
> "这是我的个人网站，整合了我的项目、技能和经历，方便您快速了解我的技术能力。"

### 2. 首页引导（1 分钟）

**重点展示**:
1. **Hero Section**: 个人简介 + 技能标签
2. **技能可视化**: 技术栈熟练度
3. **项目画廊**: 3 个核心项目

**面试话术**:
> "首页展示了我的核心技能和项目，您可以看到一个视觉化的技术栈，包括我最擅长的 Vue.js、TypeScript 等。"

### 3. 项目深度讲解（2-3 分钟）

**选择 1-2 个代表性项目**:

```
项目 1: 企业级数据可视化平台
├── 技术栈: Vue 3 + TypeScript + ECharts
├── 亮点: 实时数据、复杂交互
└── 成果: 性能提升 40%, 用户满意度 95%

项目 2: 电商小程序商城
├── 技术栈: Uniapp + Vue 3 + Pinia
├── 亮点: 跨平台、高并发
└── 成果: 日活 10k+, 转化率提升 25%
```

### 4. 关于页技术细节（1 分钟）

**重点**:
- 工作经历 → 展示项目经验
- 教育背景 → 学习能力和理论基础
- 技术认证 → 持续学习意愿

## 💬 面试交流技巧

### 常见问题预测

**Q: 为什么选择 Vue 3 而不是 React？**
> "Vue 3 的组合式 API 更符合我的开发习惯，同时 TypeScript 支持更好。Vue 3 的响应式系统也更加优雅。"

**Q: 你的网站为什么使用 GitHub Pages？**
> "GitHub Pages 能无缝集成到开发流程中，实现自动化部署。对于静态网站来说是最经济高效的方案。"

**Q: 网站中哪些技术是核心亮点？**
> "TypeScript 类型安全、响应式设计、GitHub Actions 自动化部署，以及 SPA 路由刷新 404 问题的解决。"

### 主动引导话题

- "我在项目中特别注重代码质量，使用了 TypeScript 进行类型检查"
- "我关注性能优化，Vite 构建后包体积不到 100KB"
- "我实现了自动化部署流程，使用了 GitHub Actions"

## 🛠️ 常见问题应对

### 场景 1: 网络问题，网站打不开

**解决方案**:
- 使用本地演示 (`npm run dev`)
- 展示关键页面截图
- 打开 GitHub 仓库展示代码

### 场景 2: 面试官询问具体实现

**建议**:
- 打开 Chrome DevTools 展示响应式
- 展示 GitHub Actions 构建日志
- 展示 TypeScript 类型检查

### 场景 3: 移动端展示被要求

**方案**:
- 使用浏览器开发者工具模拟移动端
- 或者直接在手机浏览器访问

## 🎯 演示优化建议

### 第一分钟黄金时间
- 展示最核心的项目
- 突出最大的技术亮点
- 强调成果和数据

### 技术深度匹配
- 初级工程师 → 简洁明了，突出学习热情
- 中级工程师 → 技术选型对比，工程化实践
- 高级工程师 → 架构设计，性能优化

### 展示方式
- 不要照本宣科
- 展示代码和构建过程
- 结合图表和数据
- 准备 30 秒精简版介绍

## 📊 成功指标

### 简历通过率
- 网站作为简历附件
- 在简历中显著位置标注网站链接
- 通过网站链接进行面试邀约

### 面试成功
- 面试官主动浏览网站
- 基于网站内容进行技术讨论
- 项目展示引发技术共鸣

## 🎨 个性化定制

### 针对不同岗位
- 前端岗位 → 突出 Vue/React 技术栈
- 全栈岗位 → 增加后端项目展示
- UI 岗位要求 → 强调动画和交互

### 行业特点
- 互联网 → 展示业务数据和成果
- 金融 → 突出安全和性能
- 教育/医疗 → 强调易用性和可访问性

## 🔗 GitHub 仓库配合

### 简历中的引用
```
个人主页: my-portfolio.github.io
GitHub: github.com/yourname
```

### 代码质量展示
- **README**: 项目说明清晰
- **Commit 历史**: 活跃且有逻辑
- **文档**: 包含详细注释和文档
- **代码整洁**: 没有临时测试代码

## 🎯 总结

面试时展示个人网站是**加分项**，但不是决定因素：

✅ **正确的做法**:
- 演示要自然，脚本化要适度
- 重点展示技术深度和解决问题的能力
- 结合具体项目讲解
- 准备应对技术问题

❌ **避免的误区**:
- 不要只是浅尝辄止
- 不要堆砌技术名词
- 不要忽视基础开发能力
- 不要依赖网站而缺乏深入理解
